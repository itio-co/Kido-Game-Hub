## 1. จุดประสงค์ / Pitch
หน้าแอดมิน `/never/god` และ API `/never/api/god/*` สำหรับดูผู้เล่น รอบคะแนน อีเวนต์ และทะเบียนโมดูล แยกจาก core ใน 0.6.11 โดยพฤติกรรมและการล็อกอินไม่เปลี่ยน

## 2. แฟนตาซีของผู้เล่น
ไม่มีฝั่งผู้เล่น ใช้โดยคนดูแลเกม

## 3. Core loop
1. เปิด `/never/god` 2. ใส่รหัส `GOD_ADMIN_PASSWORD` 3. ได้คุกกี้เซสชัน 12 ชม. 4. ดูแดชบอร์ด / ผู้เล่น / เกม / อีเวนต์ / โมดูล

## 4. กฎและ invariants
- รหัสผ่านไม่ถูกเก็บใน JS เซสชันเป็นคุกกี้ `nes_god` (HttpOnly, Secure, SameSite=Strict, path `/never`) ลงนาม HMAC
- ล็อกอินผิด 5 ครั้งล็อก 15 นาทีต่อ IP (IPv6 ใช้ prefix /64) ตาราง `god_login`
- ไม่เลือกและไม่ส่ง `token_hash`
- โมดูลนี้มีแค่หน้าแอดมินและ API ไอคอนลอยในเกมอยู่ที่โมดูล `god-mode`
- ชนิดโมดูล `edition` ใน registry เก่าถูกจัดกลุ่มเป็น `pack`
- เกมย่อยแสดงกติกาที่ build นี้เล่นได้ และจำนวนรอบต่อ `ruleset` จาก D1

### บทบาทผู้ใช้ (2.2.0)
- มี 3 บทบาท เรียงจากต่ำไปสูง: `player` (ค่าเริ่มต้นของทุกคน) < `god` < `super_god` เก็บที่คอลัมน์ `players.role` เซิร์ฟเวอร์อ่านจาก D1 เสมอ ไม่เชื่อค่าที่ไคลเอนต์ส่งมา ค่าที่ไม่รู้จักถือเป็น `player`
- ผู้ที่ล็อกอินด้วย `GOD_ADMIN_PASSWORD` (คุกกี้เซสชัน) ทำหน้าที่เป็น `super_god` เหมือนเดิมทุกอย่าง ไม่ต้องมีผู้เล่นรองรับ
- ผู้เล่นเรียก API ด้วย Bearer token ของตัวเองได้ บทบาทมาจาก D1: `god` ใช้ได้เฉพาะ `GET /me` และ `POST /snapshots` (แชร์ลิงก์ตรวจข้อมูล) ส่วนที่เหลือของ `/api/god/*` ต้องเป็น `super_god` เท่านั้น (ผู้เล่นบทบาท `player` ได้ 403 ไม่ใช่ 401)
- ทุก endpoint ที่จำกัดบทบาทผ่านด่านเดียวคือ `requireRole(req, env, min)` ใน `server.ts` คืนค่าผู้เรียก `{role, via, playerId}` หรือ Response 401 (ไม่มีเซสชัน/โทเคนที่ถูกต้อง) / 403 (บทบาทต่ำเกินไป) ฟีเจอร์ใหม่ที่ต้องจำกัดสิทธิ์เรียกใช้ตัวนี้ ไม่เขียนเช็กเอง
- เปลี่ยนบทบาทด้วย `POST /players/:id/role` `{role, confirmSuperGod?}` เฉพาะ `super_god`:
  - ผู้เล่นต้องลงทะเบียนแล้ว (มี token) เพราะ `playerId` ที่ยังไม่ลงทะเบียนเปิดเผยบนอันดับ ใครก็ลงทะเบียนแย่งได้
  - การตั้งหรือถอน `super_god` ทำได้เฉพาะผ่านเซสชันรหัสผ่านแอดมิน ไม่มีทางทำเองจากฝั่งผู้เล่น และ `super_god` ที่เป็นผู้เล่นก็ตั้งคนอื่นเป็น `super_god` ไม่ได้
  - ผู้เล่นเปลี่ยนบทบาทของตัวเองไม่ได้ (`self-change`) การลด `super_god` ต้องส่ง `confirmSuperGod: true`
  - บันทึก `role_updated_at` และ `role_updated_by` (`password` หรือ playerId ของ super god) ใช้ compare-and-swap กับบทบาทเดิม ชนกันตอบ 409 `conflict`
- หน้าผู้เล่นมีคอลัมน์ป้ายบทบาท ปุ่ม «เลื่อนเป็น GOD» / «ลดเป็นผู้เล่น» / «ลดเป็น GOD» พร้อมกล่องยืนยัน และหน้ารายละเอียดมีปุ่ม «ตั้งเป็น SUPER GOD» (ผ่านเซสชันรหัสผ่านเท่านั้น) ผู้เล่นที่ยังไม่ลงทะเบียนกดไม่ได้

## 5. Input / การควบคุม
ฟอร์มรหัสผ่าน เมนูด้านข้าง แท็บ ช่องค้นหา ปุ่มลบรอบ (มี confirm) ใช้ได้บนจอ 390px (ตารางเลื่อนข้าง)

บนมือถือ (Chrome Android) ปิด pull-down-to-refresh ของเบราว์เซอร์ด้วย `overscroll-behavior-y: none` ที่ `html`/`body`/`#god` ตาราง รายการ และบล็อก `pre` ในหน้าใช้ `overscroll-behavior-y: contain` จึงเลื่อนในกรอบได้ตามปกติ แต่ไม่ส่งต่อแรงดึงไปรีเฟรชหน้า

## 6. คะแนนและความยาก
ไม่ให้คะแนน แสดงสถิติรายระดับและรายกติกา

## 7. Progression

## 8. Content / config surface
รหัสผ่านเป็น secret ของ Worker ไม่ได้อยู่ใน repo ทะเบียนโมดูลมาจาก `dist/modules.json` ผ่าน `GET /never/api/god/modules`

## 9. UX / หน้าจอ
`God.svelte` + `GodModule.svelte` บูตจาก `main.ts` (`god.html`)

- `#/dashboard` จำนวนผู้เล่น รอบ คน active
- `#/players` และ `#/players/<id>`
- `#/games` และ `#/games/<moduleId>`: ภาพรวม, กระดาน, GDD, ตารางกติกา (runs / players)
- `#/events` กรวยคดี
- `#/modules` จัดกลุ่มตาม kind รวม `admin` และ `pack`
- `#/wishes` คำขอที่ส่งมาจากโหมด GOD ในเกม ใหม่สุดก่อน กรอง «เฉพาะที่ยังไม่อ่าน» ได้ เปิดภาพหน้าจอและลิงก์ตรวจข้อมูล และกดทำเครื่องหมายว่าอ่านแล้ว (เฉพาะ super god)

## 10. Data & telemetry (ฟิลด์บนเซิร์ฟเวอร์)
`server.ts` ตอบใต้ `/never/api/god` (เซสชันรหัสผ่าน หรือ Bearer ของผู้เล่นตามบทบาท):

| เมธอด | เส้นทาง | ทำอะไร |
|---|---|---|
| POST | `/login` `/logout` | เซสชัน |
| GET | `/me` | ตอบ `{role, via}` ใช้ได้ตั้งแต่ `god` |
| GET | `/dashboard` `/players` `/players/:id` | อ่าน (`super_god`) ตอบ `role`, `role_updated_at` |
| POST | `/players/:id/role` | เลื่อน/ลดบทบาท (`super_god`) |
| POST | `/snapshots` | สร้างลิงก์แชร์ (ตั้งแต่ `god`) |
| PATCH/DELETE | `/players/:id` | เปลี่ยนชื่อ / ลบ |
| GET | `/games` | สถิติรายระดับ + `byRuleset` |
| GET | `/games/:game/board?difficulty=&ruleset=` | กระดาน `ruleset` ว่าง = ทุกรอบ |
| DELETE | `/runs/:sessionId` | ลบรอบ |
| GET | `/events` `/modules` | กรวยคดี / registry |
| POST | `/wishes` (และทางเข้าใช้ในเกม `POST /api/wishes`) | เก็บคำขอ + ภาพหน้าจอ + state ที่กรองความลับแล้ว ต้องมีบทบาท god ขึ้นไป (`requireRole(..., 'god')`) ถ้าส่งด้วย Bearer จะเก็บ playerId และบทบาทด้วย |
| GET | `/wishes?since=&unread=1&limit=&order=` | รายการคำขอ (เมทาดาทาเท่านั้น) `since` เป็น ISO หรือ `YYYY-MM-DD` ตามเวลากรุงเทพฯ รวมค่าที่เท่ากัน เรียงเก่าไปใหม่ เฉพาะ super god |
| GET | `/wishes/:id` `/wishes/:id/screenshot` | รายละเอียด + state / ไฟล์ภาพ เฉพาะ super god |
| POST | `/wishes/mark-read` | `{ids:[…]}` ทำเครื่องหมายว่าอ่านแล้ว (สูงสุด 100) เฉพาะ super god |

รายละเอียดการเก็บ ขีดจำกัด และสคริปต์ดึงคำขอ อยู่ใน `docs/god-wish-th.md`
