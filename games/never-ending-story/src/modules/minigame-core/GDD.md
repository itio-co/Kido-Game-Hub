## 1. จุดประสงค์ / Pitch
เฟรมเวิร์กที่มินิเกม กลไก rhythm แพ็ก และโหมด challenge ใช้ร่วมกัน: ช่วงชีวิตของรอบ คีย์กติกา ลิงก์แชร์ โทเคนคะแนน เปลือก HUD ของกติกา และไดอะล็อกผลชนะที่ใช้ร่วมกันได้

## 2. แฟนตาซีของผู้เล่น
ผู้เล่นไม่เห็นโมดูลนี้ตรงๆ เห็นป้ายกติกา ลิงก์ท้าเพื่อน และผลส่งคะแนนเหมือนเดิม

## 3. Core loop
1. `defineMinigame` ลงทะเบียนโมดูล (โหมด practice / story / challenge)
2. `minigameRoute` แยกแฮช `#/challenge` `#/play/` `#/leaderboard`
3. `nextPhase` เปลี่ยน ready → play → result (มี pause/resume ใน API)
4. `seededPath` + `withChallenger` สร้างลิงก์
5. `submitFinishedRun` แพ็ก protobuf แล้วเข้าคิว `POST /api/runs`

## 4. กฎและ invariants
- ไม่มีตัวเลขเกมของตัวเอง ไม่มี `ruleset.json` การเปลี่ยนพารามิเตอร์เกมยังอยู่ที่โมดูลนั้น
- ลิงก์และโทเคนได้ไบต์เดิม: `runProto.ts` ย้ายมาที่นี่ `challenge/proto.ts` ส่งต่อให้ Worker
- คีย์กติกาเรียงชื่อโมดูล (`canonicalRuleset`) เหมือน `src/lib/ruleset.ts` ซึ่ง re-export จากที่นี่
- ปุ่ม pause ยังไม่ขึ้นบนจอ เกมเรียก `nextPhase(..., 'end')` ตอนจบรอบเท่านั้น

## 5. Input / การควบคุม
`RulesetBanner` และ `UnsupportedRuleset` เป็นเปลือกที่ใช้ใน rhythm และ challenge ปุ่มเล่นกติกาปัจจุบันกับออก

## 6. คะแนนและความยาก
ไม่คำนวณคะแนน ส่งรายงานที่เกมคำนวณแล้ว (`ChallengeRunPb`) พร้อม `ruleset`

## 7. Progression
ไม่มีสูตรดาวของตัวเอง ไดอะล็อกผลชนะแสดงดาวที่เกมคำนวณมาแล้ว และเก็บสถิติที่ดีที่สุดไว้ในเครื่องที่คีย์ `nesg.minigame-best.v1` แยกต่อเกมและระดับความยาก (`jig:easy` / `jig:medium` / `jig:hard` จากป้ายไทยหรืออังกฤษ รวม `normal` เป็น `medium`) หรือด่านฝึก (`jig:practice:3`) แถบหัวและป้ายสถิติใหม่เทียบเฉพาะสถิติระดับเดียวกัน

เกมจับเวลาใช้เวลาที่น้อยกว่าเป็นสถิติที่ดีกว่า (`applyBest`) เกมคิดคะแนนใช้คะแนนที่มากกว่าเป็นสถิติที่ดีกว่า (`applyBestScore`) รอบแรกของระดับนั้นนับเป็นสถิติใหม่ คีย์เก่าที่ไม่มีระดับความยาก (เช่น `jig`) ถูกทิ้ง ไม่ย้ายไปทุกระดับ คีย์ภาษาไทยอย่าง `jig:ง่าย` ย้ายเป็น `jig:easy` ฟังก์ชัน `starsFromHints` ให้ดาว 3 / 2 / 1 ตามจำนวนคำใบ้ 0 / 1 / 2 ขึ้นไป สำหรับเกมที่ใช้คำใบ้

## 8. Content / config surface
เกมส่ง `gameCopy(prefix)` ไปอ่าน `src/locales` · ข้อความไดอะล็อกผลชนะอยู่ที่คีย์ `minigame.win*`

## 9. UX / หน้าจอ
ป้าย `data-testid="ruleset-banner"` และการ์ด `data-testid="ruleset-unsupported"`

`WinResultDialog` (`data-testid="minigame-win-dialog"`) เป็นแผ่นมืดกึ่งกลางสไตล์เดียวกับไดอะล็อกออกจากเหตุการณ์: ชื่อใหญ่ เยี่ยมมาก! คำว่าเล่นชนะแล้ว (หรือข้อความย่อยที่เกมส่งมา) ระดับความยาก ดาวมีแอนิเมชัน สถิติของรอบเทียบสถิติดีที่สุดของระดับนั้น (เวลา หรือคะแนน ตาม `metric`) ป้ายสถิติใหม่เมื่อทำได้ดีกว่าสถิติระดับเดียวกัน และจำนวนคำใบ้เมื่อเกมมีคำใบ้

ในโฟลว์คดีมีปุ่มหลัก ต่อไป (`data-testid="minigame-win-continue"`) กดแล้วไปต่อโฟลว์เดิมของเกม (เช่น ได้หลักฐานหรือกลับไปที่คดี) ในเกมที่เล่นอิสระมีปุ่ม เล่นอีกครั้ง (`data-testid="minigame-win-replay"`) และ ปิด (`data-testid="minigame-win-close"`) กดพื้นหลังหรือ Escape ไม่ปิด

## 10. Data & telemetry (ฟิลด์บนเซิร์ฟเวอร์)
ฟิลด์ protobuf เดิม (ดู `proto/challenge_run.proto`) รวม `ruleset` ช่อง 15 คอลัมน์ D1 ไม่เปลี่ยน

ตั้งแต่ 1.2.0 รอบที่ส่งด้วย token ของผู้เล่นและได้คะแนนมากกว่า 0 นับเป็นชัยชนะของบอร์ดสตรีคบนเซิร์ฟเวอร์ (ครั้งเดียวต่อ `sessionId`) มินิเกมที่ไม่ส่งรอบ (ในคดี ฝึกเล่น) เรียก `reportWin(game)` แทน กติกาสตรีคอยู่ใน GDD ของ core หัวข้อ 9.3
