## 1. จุดประสงค์ / Pitch
คดีแรกของเกม: ตามหาอัลบั้มครอบครัวที่หายไปในบ้านย่า

## 2. แฟนตาซีของผู้เล่น
นักสืบตัวน้อยที่ค้นบ้านย่า เก็บหลักฐาน และฟังเรื่องครอบครัว

## 3. Core loop
1. รับคดีจากย่า 2. สำรวจห้อง เก็บหลักฐาน 3. แก้มินิเกม (crossword, jigsaw, slide) 4. ตอบคำถาม 5. ฉากจบ

## 4. กฎและ invariants
- ข้อมูลทั้งหมดอยู่ใน `public/data/case-flow.json` (pages, evidence, slots, scenes, dialogues, games, questions, goals)
- โค้ดไม่ฝังเนื้อเรื่อง ยกเว้นเกตปุ่มแผนผังบ้านที่ลงทะเบียนไว้ เพื่อไม่ให้ไฟล์เรื่องเก่าเปิดปุ่ม
- สมุดคดีมีหลักฐาน 4 ชิ้น (E01–E04) ไม่มี E05 สรุปคดีเปิดเมื่อเก็บครบ 4 ชิ้น สรุปได้แล้วได้กุญแจกล่องรูปดาวไว้ในกระเป๋า ไม่นับเป็นหลักฐาน ผู้ที่เซฟมี E05 หรือไขคดีไปแล้วได้กุญแจในกระเป๋า และตัวนับยังเป็น x/4
- จิ๊กซอว์แผนผังบ้านตั้ง `unlocksHouseMap: E04` และโมดูลนี้ลงทะเบียนเกต `E04` ไว้ด้วย ปุ่ม «แผนผังบ้าน» ในทุกฉากที่มี `map` (รวมห้องนั่งเล่น) ถูกซ่อนจนกว่าเซฟจะมี `E04` จากการชนะจิ๊กซอว์ ไฟล์เรื่องที่แคชไว้แล้วยังไม่มีฟิลด์นี้ก็ยังล็อกเหมือนกัน การแวะถาดหรือหลักฐานใบอื่นไม่นับว่าชนะ ผู้เล่นที่เซฟมี `E04` อยู่แล้วปุ่มเปิดอยู่

## 5. Input / การควบคุม
แตะฉาก / หลักฐาน / ตัวเลือก

## 6. คะแนนและความยาก
ระดับตาม `difficulties` ใน story pack

## 7. Progression
ความคืบหน้าใน `player_events` และ funnel ในหน้า god Event

## 8. Content / config surface
story pack JSON (ดู `docs/design/story-pack-format-th.md`, `docs/design/never-ending-story-game-case-01-missing-family-album-th.md`)

## 9. UX / หน้าจอ
เนื้อหานี้เล่นผ่าน `event-core` (`FlowView`): ฉากตัด, แผนผังบ้าน (ปุ่มโผล่ในห้องนั่งเล่นและทุกฉากที่มี `map` หลังชนะจิ๊กซอว์ E04 เท่านั้น), สมุดคดี, มินิเกม crossword / jigsaw / slide

## 10. Data & telemetry (ฟิลด์บนเซิร์ฟเวอร์)
`player_events`: eventId, status, progress_json

## 11. Dependencies + เวอร์ชัน
event-core ^1.0.0, core >=0.6.12, crossword, jigsaw, slide
