## 1. จุดประสงค์ / Pitch
นิยามไอเทมที่ใช้ซ้ำได้ (รหัส UUID ชนิด ชื่อ slug ไอคอน คำอธิบาย) พร้อมมุมมองไอคอนและหน้ารายละเอียด เนื้อหามาจากแพ็กที่ลงทะเบียน

## 2. แฟนตาซีของผู้เล่น
ของในกระเป๋าเป็นชิ้นจริงที่มองเห็นและหยิบดูได้ ไม่ใช่แค่ข้อความ

## 3. Core loop
1. แพ็กเรื่องเรียก `registerItems` เมื่อโหลด
2. กระเป๋าหรือกล่องไอเทมค้นด้วย slug (รหัสในเซฟ)
3. ผู้เล่นเห็นไอคอน แตะแล้วเปิดรายละเอียด ปิดแล้วกลับไปที่ช่องไอคอน

## 4. กฎและ invariants
- `id` เป็น UUID v4 ที่เขียนในไฟล์ ไม่สุ่มตอนเปิดเกม
- `kind` ที่รู้จักคือ `item` `item-photo` `item-key`
- `title` เป็นชื่อภาษาไทย มี `titleEn` ได้ และ `slug` เป็น kebab-case ไม่ซ้ำ
- เซฟกระเป๋ายังเก็บ `slug` (เช่น `album-photo` `case-key`) เพื่อเข้ากับเซฟเก่า
- `icon` และ `image` เป็นไฟล์ใต้ `public/img/` คำอธิบายภาษาไทยอยู่ในแคตตาล็อก ไม่ฝังในโค้ด
- ไอเทมที่ไม่ลงทะเบียนยังแสดงช่องได้โดยใช้รหัสดิบเป็นชื่อ จะไม่ทำให้เกมพัง

## 5. Input / การควบคุม
แตะไอคอนเพื่อเปิดรายละเอียด ปุ่มปิดรายละเอียดคืนค่าไปที่ช่องไอคอน บนจอแนวตั้ง 390x844 เป็นหลัก เป้าแตะอย่างน้อย 44px

## 6. คะแนนและความยาก
โมดูลนี้ไม่มีคะแนน

## 7. Progression
ไม่เก็บความคืบหน้าเอง ของที่ถืออยู่เป็นรายการในเซฟของ event-core

## 8. Content / config surface
แพ็กเรื่องลงทะเบียนไอเทมผ่าน `registerItems` (เช่น `event-01/items.json`)

## 9. UX / หน้าจอ
`ItemIcon` เป็นปุ่มช่องสี่เหลี่ยมมนขอบสีฟ้า มีภาพไอคอน `ItemDetail` แสดงภาพใหญ่ขึ้น ชื่อ และคำอธิบาย ตัวอักษรอ่านง่าย

## 10. Data & telemetry (ฟิลด์บนเซิร์ฟเวอร์)
ไม่ส่งข้อมูลขึ้นเซิร์ฟเวอร์เอง

## 11. Dependencies + เวอร์ชัน
`core >= 0.6.24`
