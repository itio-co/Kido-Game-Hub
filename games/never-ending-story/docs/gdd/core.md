# GDD: Core / เกมหลัก (`core`)

| ฟิลด์ | ค่า |
|---|---|
| kind | core |
| เวอร์ชัน | app (ตาม `package.json`, ตอนนี้ 0.6.45) |
| เทมเพลต | `docs/gdd/TEMPLATE.md` |
| อ้างอิง | `docs/design/never-ending-story-game-spec-v0.4-th.md` |

## 1. จุดประสงค์ / Pitch
เปลือกแอปของ Never Ending Story: ห้องโถงบ้านย่า, เซฟ, i18n, cloud sync, prologue. เฟรมมินิเกมอยู่ `minigame-core` เฟรมเหตุการณ์อยู่ `event-core` หน้า admin อยู่โมดูล `god` ไอคอน GOD ในเกมอยู่โมดูล `god-mode`

## 2. แฟนตาซีของผู้เล่น
เป็นหลานที่กลับมาบ้านย่ามะลิ ช่วยย่าไขคดีของเก่าในบ้าน (ย่ามะลิผมสั้นสีเงินปล่อยหลวม ไม่มวยผม)

## 3. Core loop
1. เข้าเกม → prologue (ครั้งแรก) → ตั้งชื่อ (เปลี่ยนได้ภายหลังในตั้งค่า)
2. ห้องโถง: เลือกคดี / แผนผังบ้าน / สมุดคดี / มินิเกม
3. `event-core` เล่นฉาก บทสนทนา หลักฐาน และเรียกมินิเกม
4. จบคดี → เซฟความคืบหน้า และ sync ขึ้นเซิร์ฟเวอร์

## 4. กฎและ invariants
- โค้ดเป็นภาษาอังกฤษ ข้อความไทยอยู่เฉพาะ `src/locales/*.json`
- โมดูลอื่นเข้าถึงกันผ่าน public entry (`index.ts`) เท่านั้น ตรวจด้วย `npm run check:modules`
- ไม่พิมพ์ player token ลง log
- `/never/god/*` และ `modules.json` เป็น network-only ใน SW และเป็น admin-only (โค้ดอยู่โมดูล `god`)
- กระดานคะแนนแยกด้วยกติกา (`runs.ruleset`) ไม่แยกด้วยเวอร์ชันแอป

## 5. Input / การควบคุม
แตะ/คลิกบนมือถือแนวตั้ง 390x844 เป็นหลัก แถบล่างมีปุ่มแผนผังบ้าน กระเป๋า และสมุดคดีเป็นปุ่มไอคอนวงกลมขอบสีฟ้าขนาดอย่างน้อย 44px (ชื่อปุ่มอยู่ใน aria-label/title) ทั้งสามปุ่มอยู่ระดับเดียวกับปุ่มย้อนกลับ (ขอบล่างและเส้นกึ่งกลางเดียวกัน รวม safe-area) และซ่อนตอนเล่นมินิเกมทุกชนิด (จิ๊กซอว์ ครอสเวิร์ด สไลด์ ฯลฯ) คงปุ่มย้อนกลับไว้ ข้อความสถานะด้านล่าง (รวมข้อความหลักฐาน) อยู่เหนือแถบปุ่มโดยมีช่องว่างอย่างน้อย 16px จึงไม่ทับปุ่ม ปุ่มแผนผังบ้านใช้เงื่อนไขเดียวกันทุกฉากที่มีแผนผัง รวมห้องนั่งเล่น ยังล็อกอยู่จะโชว์ไอคอนพร้อมเครื่องหมายกุญแจ แตะแล้วขึ้นข้อความว่าต้องต่อแผนผังให้เสร็จก่อน และไม่เปิดแผนผัง แม้จะเคยจบคดีมาแล้วก็เปิดได้เมื่อเกตหลักฐานปลดล็อกในรอบนี้เท่านั้น ปลดล็อกเมื่อ event-core ปลดล็อกแล้ว (คดี 1 คือหลังชนะจิ๊กซอว์แผนผัง) ไม่เปิดจากแฟล็กในเซฟหรือการแวะฉาก

## 6. คะแนนและความยาก
core ไม่มีคะแนนเอง คะแนนมาจากมินิเกม / challenge / rhythm

## 7. Progression
ความคืบหน้าคดี (`save`), `prologueSeen`, ชื่อผู้เล่น, ไอเทมในบ้าน

## 8. Content / config surface
story pack JSON (`public/data/case-flow.json`) และรูปใน `public/img/` ปรับได้โดยไม่แตะโค้ด ดู `docs/design/story-pack-format-th.md`

## 9. UX / หน้าจอ
Prologue, Hub, FlowView, Settings, Leaderboard. god admin อยู่ในโมดูล `god` ไอคอน GOD ในเกมอยู่ในโมดูล `god-mode`

ชื่อที่แสดงในเกมและบนกระดานคะแนนคือชื่อเล่นของผู้เล่น (ไม่ใช่ชื่อตัวละครในเรื่อง เช่น หนู หรือย่า) ตั้งครั้งแรกตอนจบโปรล็อก ในหน้าตั้งค่าสามารถดู แก้ และสุ่มชื่อใหม่จากรายชื่อเล่นที่ใช้กันทั่วไป (ไทยหรืออังกฤษตามภาษาของแอป) ชื่อยาว 2–20 ตัว ใช้ได้เฉพาะอักษรไทย/อังกฤษ ตัวเลข เว้นวรรค และ _ . - บันทึกไว้ในเครื่องที่ `nesg.playerId.v1` และส่งไปเซิร์ฟเวอร์ด้วย `PATCH /api/players/:id` ตามโทเคนเดิม กระดานคะแนนอ่านชื่อจากระเบียนผู้เล่น


ตั้งแต่ 0.6.38 กล่องกำลังโหลด (`src/components/LoadingDialog.svelte`) เป็นไดอะล็อกกลางจอสไตล์เดียวกับกล่องยืนยันออกจากเหตุการณ์ (พื้นเข้ม ขอบฟ้า) วาดทับบน `.phone` นอก `.stage` จึงไม่ถูกเฟดจางไปด้วย `event-core` ใช้ตอนข้ามฉากการ์ตูน และโมดูลอื่นเรียก `session.runWithLoading` ได้ ข้อความใน `loading.title` / `loading.body`

### 9.1 ปฏิทินบนผนังห้องของฉัน (0.6.26)
- แตะปฏิทินบนผนัง → หน้ารายละเอียดปฏิทิน มีเมนู **เปลี่ยนปฏิทิน** (ตั้งแต่ 0.6.27 ย่อไว้ทุกครั้งที่เปิดหน้า เห็นแค่ปุ่มหัวข้อพร้อมชื่อแบบปัจจุบันและลูกศร แตะเพื่อกาง/ย่อ หน้าปฏิทินเป็นเนื้อหาหลัก; ตั้งแต่ 0.6.28 เฉพาะเนื้อหาเลื่อนได้ ปุ่มปิดอยู่นอกส่วนที่เลื่อน จึงไม่บังปุ่มใด และกางเมนูแล้วเลื่อนให้เห็นตัวเลือกครบ): ห้องเด็ก (ปฏิทินเดิมที่วาดอยู่ในฉาก), บ้านไม้, ท้องฟ้ายามค่ำ (ล็อกจนจบคดี 01 กติกาเดียวกับธีมเดิม), สวนใบไม้ (ธีมใหม่) และปุ่ม **เก็บปฏิทินลงจากผนัง** / **แขวนปฏิทินกลับที่เดิม**
- เลือกแบบไหน ปฏิทินบนผนังและสีหน้ารายละเอียดเปลี่ยนตามกัน (ธีมใน `player-room.json` มีฟิลด์ `wall` ผูกกับแบบบนผนัง) เก็บลงแล้วสีหน้ารายละเอียดคงเดิม แขวนกลับจะได้แบบที่ตรงกับธีมปัจจุบัน
- เซฟ: `save.player.room.calendar` = `original` | `none` | `wooden-home` | `night-sky` | `garden` ค่าเริ่มต้น `original` ค่าที่ไม่รู้จัก หรือท้องฟ้ายามค่ำที่ยังไม่จบคดี 01 กลับเป็น `original` (`src/lib/calendarDecor.ts`)
- การวาด (`RoomView`): ฉากหลัง (มีปฏิทินเดิมวาดอยู่) → แผ่นผนังว่าง `img/decor/calendar-wall-patch.png` เมื่อค่าไม่ใช่ `original` → รูปปฏิทินแบบใหม่ `img/decor/calendar-<แบบ>.png` ทุกไฟล์ขนาด 720×1280 RGBA วางตรงกับฉากหลังแบบ object-fit เดียวกัน
- แผ่นผนังว่าง v4 ปิดทั้งตัวปฏิทิน เชือก ตะปู และเงาตกกระทบด้านล่าง/ขวา แล้วเติมผนังด้วย harmonic fill จากผนังสะอาดรอบ ๆ พร้อมเกรนเท่าผนังจริง ไม่เหลือเงาดำ ตะขอไม้ข้าง ๆ ไม่ถูกแตะ
- ตั้งแต่ 0.6.29 ทุกแบบมีขนาดและตำแหน่งเท่าปฏิทินเดิมในฉาก: ตัวปฏิทิน (หัวถึงขอบล่างกระดาษ) x 251–354, y 371–482 (104×112 px บนฉาก 720×1280) และตะปูบนสุดที่ (301, 338) คลาดได้ ±2 px ตรวจใน `tests/calendarAssets.test.mjs` สลับแบบแล้วขนาดไม่เปลี่ยน
- ตั้งแต่ 0.6.30 ขอบปฏิทินสร้างจากรูปทรงเรขาคณิตแทนการตัดตามสี: ตัวปฏิทินเป็นสี่เหลี่ยมมุมมนที่ fit กับขอบภาพ วาดแบบ supersample 8 เท่าให้ขอบตรงและนุ่ม เชือกเป็นเส้นสองเส้นจากตะปูถึงหัวปฏิทิน ตะปูเป็นวงกลม สีที่ขอบดึงจากเนื้อในของปฏิทิน (ไม่มีสีผนังติดขอบ) ขอบล่างและขอบข้างทาสีใหม่ให้เป็นขอบกระดาษเส้นเดียว เงาเป็นชั้นแยกที่จางหายเอง ตรวจบนพื้นสีชมพูเข้มและใน `tests/calendarAssets.test.mjs` (ไม่มีจุดลอย ขอบไม่เป็นขั้นบันได เงาไม่ถูกตัด)
- รูปปฏิทินแบบใหม่เก็บเฉพาะตัวปฏิทิน (ขอบตัดแน่น ดึงสีขอบจากด้านใน ไม่มีขอบขาว) ส่วนรอบตัวเป็นเงาสัมผัสสีดำโปร่งแบบเดียวกันทุกแบบ ไม่มีพิกเซลรอบตัวที่สว่างกว่าผนัง

### 9.2 รูปปู่บนชั้นของที่ระลึก (0.6.31)
- ตั้งแต่ 0.6.37 เมื่อไขคดี 01 เสร็จแล้วกลับห้องของฉัน จะมีฉากการ์ตูน 1 หน้า (`photo-placement.jpg` วาดจากฉากห้องเดิมกับชั้นรูปปู่) ว่าหนูวางรูปคุณปู่บนชั้นของที่ระลึก แตะหรือข้ามแล้วรูปถึงปรากฏบนชั้น และบันทึกใน `save.player.decor` ชั้นว่างอยู่จนกว่าจะวาง เล่นซ้ำคดีไม่เก็บรูปออก รีเซ็ตเซฟแล้วชั้นว่างอีกครั้ง เซฟเก่าที่จบคดีแล้วยังไม่ได้วางจะเห็นฉากนี้ตอนกลับห้อง (`shouldPlayPhotoPlacement`) รูปที่วางคือไอเทม `album-photo` (รูปปู่ตอนหนุ่ม) จากโมดูล `item`
- จบคดี 01 แล้ววางรูปปู่บนชั้นของที่ระลึก (0.6.25) → กรอบรูปปรากฏบนชั้น ตั้งแต่ 0.6.31 แตะชั้นอีกครั้งจะเปิดหน้ารายละเอียดรูป: เห็นกรอบรูปแบบเดียวกับบนชั้น และเมนู **จัดรูปบนชั้น** ที่ย่อไว้ทุกครั้งที่เปิด (แบบเดียวกับเมนูเปลี่ยนปฏิทิน) กางแล้วมีปุ่ม **เก็บรูปลง** หรือ **วางรูปกลับบนชั้น** ปุ่มปิดอยู่นอกส่วนที่เลื่อน จึงไม่บังเมนู (`src/components/PhotoPanel.svelte`)
- เซฟ: `save.player.room.grandpaPhoto` = `shelf` | `stored` ค่าเริ่มต้น `shelf` (เซฟเก่าที่วางรูปแล้วจึงยังเห็นรูปบนชั้น) ค่าที่ไม่รู้จักกลับเป็น `shelf` ซิงก์ขึ้นเซิร์ฟเวอร์ใน home doc คู่กับ `calendar` (`src/lib/decor.ts`, `normalizeRoomDecor`)
- เก็บรูปลงแค่ซ่อนรูป: ช่อง `decor` ของชั้นยังเก็บ `📷 รูปปู่` (บันทึกว่าเรื่องวางรูปแล้ว) ความคืบหน้าคดี รางวัล และ flag ต่าง ๆ ไม่ถูกแตะ วางกลับเมื่อไหร่ก็ได้ ตอนเก็บไว้ จุดบนชั้นแสดงเป็น + เหมือนช่องว่าง
- ภาพ: ฉากหลังมีชั้นว่างอยู่แล้ว เก็บรูปจึงแค่ไม่วาดชั้น `img/decor/keepsake-shelf-grandpa-photo.png` ไม่ต้องมีแผ่นปะ ตั้งแต่ 0.6.31 รูปนี้สร้างขอบจากรูปทรง (วิธีเดียวกับปฏิทิน 0.6.30): กรอบเป็นสี่เหลี่ยม x 452–556, y 265–388 วาด supersample 8 เท่า สีขอบดึงจากเนื้อในกรอบ เงาเป็นชั้นแยกทอดไปทางขวาแล้วจางหาย ไม่ทับขอบชั้นด้านหน้า (y 388) แทนแผ่น AI แบบเบลอขอบเดิมที่มีขอบสีผนังและรอยดำรอบกรอบ ตรวจบนพื้นสีชมพูเข้มและใน `tests/calendarAssets.test.mjs`

### 9.3 บอร์ดสตรีคในห้องของฉัน (0.6.39, กติกาถ่านและหน้าฉลองใน 0.6.40)
- ในห้องของฉันมุมขวาล่างมีป้ายสายฟ้าพร้อมตัวเลขสตรีค แนวเดียวกับปุ่มย้อนกลับ แตะแล้วเปิดบอร์ดสตรีค (`src/components/StreakPanel.svelte`) ป้ายเรืองสีเหลืองเมื่อวันนี้นับแล้ว และเป็นสีเทาเมื่อสตรีคเป็น 0
- บอร์ดมี: หัวข้อ **สตรีคเล่นต่อเนื่อง** และถ่านสำรอง 2 ก้อนมุมขวาบน (ก้อนที่ใช้ไปแล้วจะจาง) ตัวเลขใหญ่พร้อมสายฟ้า ข้อความสถานะ แถววันในสัปดาห์นี้ จ–อา (วันที่เล่นชนะเป็นวงเหลืองมีสายฟ้า วันที่ใช้ถ่านแทนเป็นวงฟ้ามีรูปถ่าน วันนี้มีขอบฟ้า วันที่ยังไม่ถึงจาง) การ์ด **สตรีคสูงสุด** และ **ชนะทั้งหมด** บรรทัดบอกว่าทำสตรีควันนี้จะได้ถ่านคืนถ้ายังไม่เต็ม และกติกาย่อ ปุ่มปิดอยู่นอกส่วนที่เลื่อน
- เมื่อเซิร์ฟเวอร์นับสตรีควันนี้ให้แล้ว เกมแสดงหน้าต่างฉลอง (`src/components/StreakCelebrateDialog.svelte`) ครั้งเดียวต่อวันต่อเครื่อง บอกว่าทำสตรีควันนี้แล้ว พร้อมสถานะล่าสุด (จำนวนวัน สตรีคสูงสุด ชนะทั้งหมด แถวสัปดาห์ และถ่าน) ถ้าถ่านยังไม่เต็มจะได้เพิ่ม 1 ก้อน ถ้าเต็มแล้วจะบอกว่าถ่านเต็มไม่ได้เพิ่ม มีแอนิเมชันฉลองเล็ก ๆ และไม่เล่นแอนิเมชันเมื่อเครื่องตั้งให้ลดการเคลื่อนไหว
- กติกา (`src/lib/streak.ts` ใช้ทั้งเซิร์ฟเวอร์และหน้าจอ):
  - วันตัดตามเวลาไทย (UTC+7) เที่ยงคืนไทยคือวันใหม่
  - วันไหนเล่นมินิเกมชนะอย่างน้อย 1 เกม เกมไหนก็ได้ (ครอสเวิร์ด จิ๊กซอว์ เลื่อนบล็อก ในคดี ฝึกเล่น หรือท้าดวล และผัดกับย่าที่ได้คะแนนมากกว่า 0) นับเป็น 1 วัน นับให้วันละครั้งเท่านั้น ชนะเกมต่อ ๆ ไปในวันเดียวกันเพิ่มแค่การ์ด **ชนะทั้งหมด** (เพิ่มได้ไม่เกิน 100 ครั้งต่อวัน)
  - วันที่ไม่ได้เล่นชนะ ใช้ถ่าน 1 ก้อนต่อ 1 วัน สตรีคไม่ขาดแต่ไม่เพิ่ม ถ้าวันที่ขาดมากกว่าถ่านที่เหลือ สตรีคกลับเป็น 0 และถ่านหมด
  - ได้ถ่านคืน: ทุกวันที่เซิร์ฟเวอร์นับสตรีคให้ (วันละครั้ง) ถ้าถ่านยังไม่เต็ม จะได้ถ่านคืน 1 ก้อน สูงสุด 2 ก้อน เซิร์ฟเวอร์เป็นผู้ให้เท่านั้น ไม่ให้ซ้ำในวันเดียวกันแม้ส่งผลซ้ำหรือโหลดหน้าใหม่ (กติกานี้แทนการคืนถ่านทุก 7 วันของ 0.6.39)
  - เริ่มสตรีคใหม่ (ครั้งแรก หรือหลังสตรีคขาด) ได้ถ่านเต็ม 2 ก้อน จึงไม่ได้เพิ่มในวันแรก สตรีคสูงสุดไม่ลดลง
- นับตอนส่งผลขึ้นเซิร์ฟเวอร์และใช้เวลาเซิร์ฟเวอร์ ไม่ใช้เวลาในเครื่อง: รอบท้าดวลและผัดกับย่านับตอนส่งผลที่ยืนยันตัวตนแล้ว (`POST /api/runs`) มินิเกมในคดีและฝึกเล่นนับตอนชนะ (`POST /api/players/me/streak/win` จาก `reportWin` ของ minigame-core) ถ้าออฟไลน์ เครื่องจะลองส่งใหม่ภายในวันเดียวกันเท่านั้น
- เซิร์ฟเวอร์ส่ง token เข้ารหัสกลับมาด้วย ข้างในมี `{streakCount, date}` ของสตรีคล่าสุด เครื่องเก็บไว้ใน `nesg.streak.v1` พร้อมข้อมูลบอร์ดล่าสุด แล้วส่งกลับไปทุกครั้งที่ส่งผล เซิร์ฟเวอร์ถอดแล้วเทียบกับข้อมูลของตัวเอง ถ้าไม่ตรงหรือถูกแก้ ยังยึดข้อมูลบนเซิร์ฟเวอร์เสมอ และไม่บันทึก token ลง log
- ยังไม่เคยเชื่อมต่อเซิร์ฟเวอร์ บอร์ดเป็น 0 พร้อมข้อความว่าเชื่อมต่อไม่ได้ ตัวเลขบนเครื่องไม่เคยคิดเอง

### 9.4 บทบาทผู้เล่น (0.6.40; ปล่อยพร้อม god 2.2.0 และ god-mode 1.3.0)
- ทุกผู้เล่นมีบทบาท `player` (ค่าเริ่มต้น) `god` หรือ `super_god` เก็บที่ `players.role` (กติกาและโค้ดตัดสินใจ: `src/lib/roles.ts`) ผู้เล่นเปลี่ยนบทบาทตัวเองไม่ได้ ไม่มี API ฝั่งผู้เล่นสำหรับเรื่องนี้ การเลื่อน/ลดทำที่หน้าแอดมิน (`/never/god`) ด้วยรหัสผ่านแอดมินเท่านั้น (ดู GDD ของ `god`)
- `GET /api/players/me` (Bearer) ตอบ `{ok, playerId, role}` ไคลเอนต์ใช้ (`fetchMyRole` ใน `cloudSync.ts`) เพื่อแสดงปุ่ม GOD ให้ผู้เล่น god / super_god ไม่ใช่เพื่อกำหนดสิทธิ์ สิทธิ์จริงตรวจที่เซิร์ฟเวอร์ทุกครั้ง
- ฟีเจอร์ฝั่งเซิร์ฟเวอร์ที่ต้องจำกัดสิทธิ์ใช้ `requireRole(req, env, 'god' | 'super_god')` จาก `src/modules/god/server.ts` (Worker import ได้) ไม่เขียนเช็กบทบาทเอง
